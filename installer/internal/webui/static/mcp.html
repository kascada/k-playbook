Registrierung

Prüfen...

Eingetragen wird k-playbook mcp — der beim Schreiben aufgelöste absolute Pfad des installierten Binaries, nicht sein bloßer Name. Aus Dock oder Finder gestartete Clients erben die Shell-PATH nicht; ein Kommandoname wäre dort tot.

Als aktuell gilt nicht ein einziger Wert, sondern eine Menge von Formen: jeder absolute Pfad auf ein installiertes k-playbook, auch der eines anderen $HOME. Sonst erklärten Host und DevContainer sich in derselben Datei wechselseitig für veraltet. Dazu der bloße Name k-playbook — die eincheckbare Form, die kein $HOME nennt; sie wird nie geschrieben, aber auch nie überschrieben. Von selbst überschrieben wird nur der abgelöste Wrapper-Pfad k-playbook/bin/k-playbook.

Der Server löst das Projekt über sein Arbeitsverzeichnis auf, nicht über den Ort der Konfigurationsdatei. Er findet es deshalb nur, wenn der Assistent im Hauptverzeichnis geöffnet ist — dort, wo K-PLAYBOOK.yaml liegt.

Angebotene Werkzeuge

Messen...

Gemessen, nicht behauptet: die Oberfläche startet den registrierten Befehl als eigenen Prozess, schickt ihm initialize und tools/list und zeigt, was zurückkommt. Damit beantwortet dieselbe Anzeige auch, ob der Server überhaupt läuft. Gestartet wird er dabei ohne die geerbte Shell-PATH — sonst meldete der Test grün, während der aus Dock oder Finder gestartete Client scheitert.

Wozu der Server da ist

Er gibt einem Assistenten dieselbe Auskunft, die k-playbook context auf der Kommandozeile liefert: die aufgelösten Pfade, die Instruktionsdateien in Lesereihenfolge, die Remediation-Policy, die Guidelines und die effektiven Kataloge für Regeln, Reviews und Checks — mitgeliefert und projekteigen bereits zusammengeführt.

Mehr tut er nicht. Er führt keine Reviews aus, legt nichts an und verändert nichts am Projekt; das machen Commands und Skills im Assistenten. Und er entfernt seine eigene Registrierung nicht: wer den Eintrag loswerden will, löscht ihn von Hand.

Nach dem Einrichten steht der Server erst nach einem Neustart des Assistenten zur Verfügung. Claude Code fragt dabei einmal nach der Freigabe — projektbezogene Server aus .mcp.json gelten dort erst nach ausdrücklicher Zustimmung.
